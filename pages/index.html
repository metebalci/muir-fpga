muir-fpga

The MIT CADR Lisp Machine, in the fabric of a small FPGA board.

The CADR is the Lisp machine MIT designed in the 1970s. This project rebuilds it in programmable logic: the two processor boards, the bus interface, the disk controller, the display and the I/O board, as they were drawn. Every part of it is held to muir, a simulator of the same machine, tick for tick and microcycle for microcycle. The result boots MIT's own system software off a disk pack and paints the window system on a screen.

The Arty Z7-20 is the recommended board, and the one tested the most. It is the board the project was built on, and every block on its drawing has now run on it.

The Cora Z7-07S carries a smaller part of the same kind and a smaller board, with no HDMI output and no USB host for a keyboard and mouse, and the machine fits it and closes timing with nothing in the machine itself changed.

The machine itself

The CADR was a real machine. It had two processor boards, a bus interface, a disk controller, a display board and an I/O board, wired together by five cables. It is worth knowing what it was before looking at a drawing of it inside a chip.

What a CADR is: the hardware, board by board

The name

muir-fpga is muir's RTL model of the CADR, synthesized into the fabric of an FPGA and held to muir tick for tick. muir is named for Nathan Muir, the character Robert Redford plays in Spy Game (2001). In memory of Robert Redford.

Third-party material

Some of what these boards need is not this project's work, and some of it is not in the repository at all. Each entry below says whose it is, under what terms, and where in the repository those terms are recorded. Where nothing records them, it says that instead of guessing.

Digilent's pin files
Pins come from Digilent's published master constraint files and never from memory, because a wrong pin is a light that does not come on. Digilent publishes them under the MIT License. The Cora Z7-07S's master file is in its board directory byte for byte as published, beside a copy of that license as Digilent-License.txt. The Arty Z7-20's own constraint file copies out the handful of pins that design uses rather than carrying the master file, and cites the commit and digest it read them from.
muir
The simulator this machine is held to is a separate repository and is not carried here. It sits beside this one, pinned by commit in muir.commit so that a reference trace names the muir it was taken from, and it is under the same AGPL, version 3 or later.
Buildroot, U-Boot, Linux
The Linux side of a Zynq board is built rather than copied. The build fetches Buildroot 2026.02.3, and through it U-Boot 2026.01 and Linux 6.19.14, each under its own license, which for the loader and the kernel is the GPL, version 2. Nothing of theirs is in this repository. The only files of this project's that are compiled into them are the four per board named above.
Archivo, IBM Plex Mono
The two faces these pages are set in, by Omnibus-Type and by IBM. Both are under the SIL Open Font License, Version 1.1, and both are in pages/fonts/ as the unmodified Latin subsets Google Fonts serves, so that reading a page here asks nothing of a third party.
MIT's own files
The drawings on the page about the real machine, and the behavior every check in this project is held to, are read from MIT's engineering files: the drawings, wire lists, print sets and PROM images the AI Laboratory wrote between 1977 and 1981, and MIT's system software beside them. None of it is in this repository. muir carries it, recovered from the ITS backup tapes and unmodified. No statement of terms came with the engineering files and none is made up for them; the system release states its own, which is the AGPL, version 3 or later.
