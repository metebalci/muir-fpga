# The mutation list for cadr-console: bugs `console_test.c` has to catch.
#
# `mutate.py` applies each record to a copy of the sources this check builds,
# builds the check against it, and runs it.  A mutation the check FAILS on is
# a check doing its job; one the check passes is reported as SURVIVED and the
# run is red.  A record whose `@old` no longer matches its file exactly once,
# or that does not compile, is BROKEN and also fails the run --- two fabric
# mutations were once reported as surviving that had never been built.
#
# THE FORMAT is `mutations/list.txt`'s, so that anybody who has read that one
# can read this one:
#
#   @mutation  a kebab-case name; how a survivor is reported
#   @file      which of the sources this check builds to mutate
#   @why       what the check is supposed to notice, printed when it does not
#   @note      prose, repeatable; printed with @why on a survivor
#   @old       the source to replace, exactly as it stands
#   @new       what to put there; empty deletes
#   @end
#
# **THIS PACKAGE'S CHECK BUILDS `cadr-common/src/cadr_log.c`, SO RECORDS AIM
# AT IT FROM HERE.**  That is what `serial_mutations.txt` already does with
# the endpoint grammar and `usb_mutations.txt` with the input link: a file
# several packages share is held by the check that builds it, and the
# logging's own package has a shell check and no C one to put these in.  A
# bare name below is this package's; `cadr-common/src/...` is the shared file.
#
# WHERE THE LIST CAME FROM.  The console's own printing rule --- a reply to a
# person is bare and a line that is kept names its program --- and then every
# rule `cadr/cadr_log.h` states about where a line goes and how big a log may
# get, because a rule nothing exercises is not a rule.  `docs/console.md` has
# the eight mutations that were applied BY HAND to this program before there
# was a runner here; they are still to be written down as records.
#
# **THE MUTATIONS KEEP EVERY SIGNAL USED.**  `docs/mutations.md`'s rule that
# lint must not do the catching, one language along: a mutation that leaves a
# variable unread is caught by the compiler and not by the check, and a
# record caught by its own build failure is a record that tests nothing.

# **A SECOND EQUIVALENCE, REASONED AND STATED RATHER THAN FILED.**  Dropping

# `ftell`, which on a console answers 0 for ever and on a pipe fails, so
# neither ever reaches the cap.  The test is there to say what is meant and to
# stop a future size that came from counting bytes rather than from the file.

# **AN EQUIVALENCE, MEASURED, SO THAT NOBODY FILES IT AS A HOLE.**  Deleting

# --- WHICH BUILD THE FABRIC IS, page 2's word 32 --------------------------
#
# The decode's three defects: a nibble read from the wrong end, a tree state
# that looks like another, and the one value the stamp's format reserves
# being taken for a build.  What makes these worth recording is that the word
# they read is the only thing on a running board that says which bitstream it
# is carrying, and a wrong answer there is worse than none: a person who
# believes a commit goes and reads that commit's sources.

@mutation the-build-nibble-is-read-from-the-wrong-end
@file console_face.c
@why the stamp's format is seven hex digits of commit and a nibble of tree state,
@why and a decode that took the nibble from the top gets both halves wrong at once
@note Written as a shift the other way rather than as a mask, so that every
@note field stays read and the compiler has nothing to say --- the lint lesson
@note one language along.  A board carrying build `782e3a90`, a clean tree,
@note would report commit `82e3a90` and a tree of 7, which is not a state the
@note format defines: it reads as a fabric from somewhere else entirely.
@old
	b.commit = w >> 4;
	b.tree = w & 0xFu;
@new
	b.commit = w & 0x0FFFFFFFu;
	b.tree = w >> 28;
@end

@mutation a-dirty-build-says-its-tree-was-clean
@file console_face.c
@why a bring-up run against an uncommitted change is legitimate and the stamp records
@why it; a console that reported the commit alone would send somebody to sources that
@why are not what the fabric was made from
@note The nibble is still decoded and still printed; what goes is the
@note distinction between the two states, which is exactly the shape of a
@note defect somebody would introduce while tidying.  The rule at the stamp
@note is that a dirty tree is RECORDED and never refused, so the check has to
@note hold the recording and not merely the refusal.
@old
	case CONS_BUILD_MODIFIED:	b.modified = 1;		b.known = 1; break;
@new
	case CONS_BUILD_MODIFIED:				b.known = 1; break;
@end

@mutation all-ones-is-read-as-a-build
@file console_face.c
@why all ones is what an unprogrammed part reads and what a bitstream built before
@why the flows stamped them leaves behind, and `build_stamp_pack` makes sure no build
@why can ever be called it: a console that printed `commit fffffff` would invent one
@note This is the all-ones-and-all-zeros rule in its decoding form, and it is
@note the value most likely to be met on a board --- every bitstream this
@note project built before the stamp existed reads it.  The mutation keeps the
@note field and sets it, so nothing is left unread.
@old
	if (w == CONS_BUILD_NONE)
		return b;		/* stamped stays 0; there is nothing to read */
	b.stamped = 1;
@new
	b.stamped = 1;
@end

@mutation the-build-is-read-from-the-word-beside-it
@file console_face.c
@why page 2's word 32 is the build and word 33 reads UNMAPPED, so a read aimed a word
