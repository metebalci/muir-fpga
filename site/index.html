muir-fpga

The MIT CADR Lisp Machine, in the fabric of a small FPGA board.

The CADR is the Lisp machine MIT designed in the 1970s. This project rebuilds it in programmable logic: the two processor boards, the bus interface, the disk controller, the display and the I/O board, as they were drawn. Every part of it is held to muir, a simulator of the same machine, tick for tick and microcycle for microcycle. The result boots MIT's own system software off a disk pack and paints the window system on a screen.

The Arty Z7-20 is the recommended board, and the one tested the most. It is the board the project was built on, and every block on its drawing has now run on it.

The Cora Z7-07S carries a smaller part of the same kind and a smaller board, with no HDMI output and no USB host for a keyboard and mouse, and the machine fits it and closes timing with nothing in the machine itself changed.

The Arty A7-100 is a side project, taken on to see how far the machine can go on a board with no processing system at all: everything the Arm cores and Linux do on the other two boards has to have an answer in the fabric there, and it is further from finished than the Zynq boards.

The machine itself

The CADR was a real machine. It had two processor boards, a bus interface, a disk controller, a display board and an I/O board, wired together by five cables. It is worth knowing what it was before looking at a drawing of it inside a chip.

What a CADR is: the hardware, board by board

The name

muir-fpga is muir's RTL model of the CADR, synthesised into the fabric of an FPGA and held to muir tick for tick. muir is named for Nathan Muir, the character Robert Redford plays in Spy Game (2001). In memory of Robert Redford.

The work in this repository is free software under the GNU Affero General Public License, version 3 or later. That is the fabric, the checks and their reference traces, the programs that run beside the machine, the documents and these pages alike. The full text is LICENSE at the root of the repository. Almost every file in it repeats that in its own header as the SPDX identifier AGPL-3.0-or-later, so a file taken out of the repository still says what it is.

Eight files are under the GNU General Public License, version 2 or later instead, four for each of the two Zynq boards. They are the Zynq start-up routine ps7_init_gpl.c, U-Boot's default environment, the board's device tree and the -u-boot.dtsi beside it. Each of the eight is compiled into U-Boot, which is itself under that licence, and the start-up routine's register tables are Digilent's board configuration as Xilinx's tool writes it out, whose own ps7_init_gpl.c carries the same terms. Every one of them says so in its own header.

Third-party material

Some of what these boards need is not this project's work, and some of it is not in the repository at all. Each entry below says whose it is, under what terms, and where in the repository those terms are recorded. Where nothing records them, it says that instead of guessing.

Ibex
lowRISC's RISC-V core, which is the soft processor on the Arty A7-100. It is in third_party/ibex/ as published, pinned at commit 405c6d1d rather than at a release because the project has none, under the Apache License 2.0. The primitives from lowRISC's own IP library that it depends on are under that directory in a vendor/ of its own, under the same licence.
Digilent's pin files
Pins come from Digilent's published master constraint files and never from memory, because a wrong pin is a light that does not come on. Digilent publishes them under the MIT License. The Cora Z7-07S's and the Arty A7-100's master files are in their board directories byte for byte as published, each beside a copy of that licence as Digilent-License.txt. The Arty Z7-20's own constraint file copies out the handful of pins that design uses rather than carrying the master file, and cites the commit and digest it read them from.
Digilent's memory settings
The Arty A7-100's DDR3L timing comes from Digilent's own project file for that board, mig-digilent-E.0-1.1.prj, kept byte for byte as published by Digilent in github.com/Digilent/vivado-boards. The repository records the commit, the path and a digest for it; it does not record a licence for that repository, and none is assumed here.
The memory controller
That project file is the input to Xilinx's Memory Interface Generator, and what the generator writes is committed under boards/arty-a7-100/mig/gen/. Thirty-four of those seventy-three files carry Xilinx's own copyright notice and disclaimer, which grants nothing beyond a licence Xilinx itself issues and asks that the notice stay with the file. They are kept exactly as the generator wrote them.
muir
The simulator this machine is held to is a separate repository and is not carried here. It sits beside this one, pinned by commit in muir.commit so that a reference trace names the muir it was taken from, and it is under the same AGPL, version 3 or later.
Buildroot, U-Boot, Linux
The Linux side of a Zynq board is built rather than copied. The build fetches Buildroot 2026.02.3, and through it U-Boot 2026.01 and Linux 6.19.14, each under its own licence, which for the loader and the kernel is the GPL, version 2. Nothing of theirs is in this repository. The only files of this project's that are compiled into them are the four per board named above.
Archivo, IBM Plex Mono
The two faces these pages are set in, by Omnibus-Type and by IBM. Both are under the SIL Open Font License, Version 1.1, and both are in site/fonts/ as the unmodified Latin subsets Google Fonts serves, so that reading a page here asks nothing of a third party.
MIT's own files
The drawings on the page about the real machine, and the behaviour every check in this project is held to, are read from MIT's engineering files: the drawings, wire lists, print sets and PROM images the AI Laboratory wrote between 1977 and 1981, and MIT's system software beside them. None of it is in this repository. muir carries it, recovered from the ITS backup tapes and unmodified. No statement of terms came with the engineering files and none is made up for them; the system release states its own, which is the AGPL, version 3 or later.
