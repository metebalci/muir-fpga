The machine this project reproduces

The CADR is a 32-bit microcoded processor built at the MIT Artificial Intelligence Laboratory around 1978, and published as AI Memo 528 in 1980. It is the machine the Lisp Machine system was written for.

It is a general-purpose processor designed for convenient emulation of complex order codes, and on it the microcode interprets the 16-bit order code the Lisp machine compiler produces. The drawings below are read from MIT's own files, and the table at the foot says which file each one came from.

The processor

The CADR board carries the data paths and the ICMEM board the control memory. Every edge-triggered register on them takes one clock edge a microcycle. Between the edges the clock is a level, and the board reads it as one: a read phase and then a write phase.

The microinstruction

A microinstruction is 48 bits and there are four classes of it. Every one names two sources, called A and M, and two of the four also name a destination. Three bits mean the same thing in every class: STAT, ILONG and POPJ.

The map

Memory is reached through two levels of paging that turn a 24-bit virtual address into a 22-bit physical one. A page is 256 words, so the low eight bits pass through untouched. There is no state in either level: a lookup is a ripple through two memories inside one microcycle.

What is where

The physical address is 22 bits, so the Xbus can carry four million words. The top four of its 64 slots are not memory: two are I/O space and two are the whole of the Unibus. A cycle to an address nothing answers is given up on by a timer on the bus interface.

The disk

The disk controller is one board on the Xbus and it is a bus master as well as a slave: it moves blocks into main memory itself. Writing the command register starts nothing. A transfer begins when something is written to START, after the other registers have been set up.

The display

MIT's word for the display controller is the TV, and the board this project reproduces is the black-and-white SIMPLE TV. There is no colour and no grey. The picture is exactly what the software has written into the frame buffer.

The I/O board

The I/O board is the machine's half of a conversation with a person. It is a Unibus board carrying the keyboard, the mouse, two clocks, the serial port and the Chaosnet interface. It answers a block of 64 addresses, in eight groups of eight.

The light panel

A CADR has a small panel of lamps and one button, on a cable from the control memory board. Twelve of the connector's wires are used and the rest are not. Every internal memory in the machine is parity checked, and the panel is where the checks show.

The debug cable

A CADR is debugged by another CADR. The debugger's DBGOUT connector goes to the debuggee's DBGIN, and over the cable one machine's Unibus cycles run on the other machine's bus. The console program that does it is called CC, and it is Lisp software running on the debugging machine.

Where each drawing came from

Nothing above is a first-hand invention. Numbers written with a leading 0o are octal, which is how MIT writes an address.

Sources

MIT's own files

lmdoc/cadr.164
AI Memo 528, CADR, in the printing of 15 May 1980. The machine in MIT's own words.
cadr/ir.bits
The microinstruction's field diagram, the functional source and destination tables, and the sixteen diagnostic registers.
cadr/busint.erface
The five cables, the two buses they carry, and what a wait and a hang are.
cadr1/xspec.text.3
The Xbus specification: its cycles, its deskew delays, its arbitration, and the pinout of every kind of slot in the cage.
cadrwd/cadr4.wlr, cadrwd/icmem3.wlr, cadr1/busint.wlr
The wire lists the two processor boards and the bus interface were wrapped from. The light panel's connector is read from the second of them.
cadrtv/lmtv.order
The programming specification for the display board.
cadrio/, cadrdc/, cadrm/, chaos/lispm/
The drawings of the I/O board, the disk controller, the memory board and the Chaosnet interface.
sys/ucadr/promh.text
MIT's source for the boot PROM, with its comments.

Files in the System 100 release

sys/doc/disk.text
"Programming the Disk Controller": every register, the format of a block, and the two drive geometries.
sys/doc/unaddr.text
MIT's own allocation of Unibus and Xbus addresses.
sys/io1/ukbd.lisp
The keyboard's firmware, with the protocol at the end of it: the 24-bit word, the key table, and the boot combination.
sys/io1/time.lisp, sys/io1/serial.lisp
The drivers for the two clocks and the serial port, which are where their Unibus addresses are written down.
sys/window/shwarm.lisp
The window system's own use of the display, which is what fixes the shape of the screen.
